# Relational Database Schema Blueprints & Data Dictionary
**Project:** Sovereign Parametric Climate Risk Tester  
**Lead Analyst:** Lenny Wanjiru | *Dedan Kimathi University of Technology (DeKUT)*  
**Database Management Engine:** SQLite (Relational Staging Architecture)



## 1. Database Architecture Overview
To preserve data integrity, enforce absolute schema constraints, and ensure maximum execution speed during 10,000-year stochastic Monte Carlo iterations, this framework uses a decoupled local SQLite database engine (`climate_risk.db`). 

The schema maps unstructured flat-file regional observations and historical loss logs into structured, normalized entities. This relational setup eliminates data isolation, handles multi-region cross-sectional joins, and provides an optimized staging environment for downstream machine learning and solvency workflows.



## 2. Entity-Relationship & Core Table Schemas

### Table A: `climate_mesh_registry`
*   **Description:** Stores multi-year spatial-temporal climate indicators, weather indices, and satellite anomaly tracking records across localized regional quadrants.
*   **Primary Key Structure:** Composite Key `(region_id, calendar_year)` to enforce distinct time-series observations per region.

| Field Name | Data Type | Key Type | Operational Description & Mapping Constraints |
| :--- | :--- | :--- | :--- |
| `region_id` | TEXT | **PK / FK** | Unique geographical regional identifier (e.g., Alpha_West, Beta_East). Maps directly to the loss ledger. |
| `calendar_year` | INTEGER | **PK** | The specific 4-digit calendar year of observation (Range: 1996 to 2026). |
| `rainfall_mm` | REAL | - | Continuous numeric array tracking cumulative annual precipitation levels in millimeters. |
| `satellite_ndvi_score` | REAL | - | Normalized Difference Vegetation Index (NDVI) tracking real-time regional vegetation health limits. |
| `is_stress_year` | INTEGER | - | Boolean flag proxy (1 = Acute Drought Event Triggered, 0 = Normal Baseline Year). |
| `predicted_drought_risk_score` | REAL | - | Out-of-sample predictive probability score generated by the trained Ensemble Random Forest Classifier. |

### Table B: `historical_loss_ledger`
*   **Description:** Tracks historical agricultural financial impact logs, structural yield asset depletions, and sovereign parametric insurance claim payouts.
*   **Primary Key Structure:** `claim_id` (Unique alpha-numeric transaction string).

| Field Name | Data Type | Key Type | Operational Description & Mapping Constraints |
| :--- | :--- | :--- | :--- |
| `claim_id` | TEXT | **PK** | Unique serialized claim transaction identifier string (e.g., CLM_1001). |
| `region_id` | TEXT | **FK** | Relational link mapping the loss back to individual region profiles. References `climate_mesh_registry(region_id)`. |
| `calendar_year` | INTEGER | - | The historical calendar year corresponding to the financial loss incident. |
| `historical_yield_loss_metric` | REAL | - | Continuous coefficient tracking agricultural crop or livestock biomass yield reduction ratios. |
| `direct_economic_payout_usd` | REAL | - | The actual financial contingency capital volume disbursed from the fund (Capped at \$5,000,000.00 max). |

---

## 3. Data Integrity & Structural Relationships
1.  **Referential Integrity Constraints:** The schema enforces a strict **Foreign Key relationship** between `historical_loss_ledger` and `climate_mesh_registry`. Any claim entry generated within the loss table must reference a valid, pre-existing geographical region within the primary weather directory, preventing orphaned rows.
2.  **Deterministic Integrity Audits:** To verify relational integrity before launching stochastic simulations, the code executes automated cross-schema `INNER JOIN` statements to confirm that every spatial-temporal anchor matches across the database partition tables.
